# Superbrain — 0 A.D. 副驾（AI 自动打 RTS）

给 **0 A.D.: Empires Ascendant**（实测版本 0.28.0 / `a2cae4d69f`，Windows）做的**单机对战副驾**：
当你操作不过来时，让 AI 接管军队的微操和后方经济运营。目标是"打不过的时候它越强越好"。

> ## ⚠️ 先说清楚
> **这个仓库里的全部代码都是由 AI agent 生成的，没有经过人工逐行审核。**
> 包括 mod、Node 后端、前端、测试脚本、文档，全都写过就直接跑在真游戏上了。
> 里面的注释记录了大量"实盘试出来的结论"和负结果（哪些做法更慢、哪些会把经济搞崩），
> 但这些结论同样来自 AI 的观察，不一定正确。**不要把它当成可信赖的代码质量范例。**
>
> 只做**单机**用途。检测到多人对局会自动关掉接管（代码里有这条硬约束），
> 没有联网对战作弊的意图，也不要去这么用。

## 它是什么

两部分，靠文件 IPC 通信（不注入引擎、不改引擎二进制）：

| 目录 | 是什么 |
|---|---|
| `mod/` | 游戏内 mod：`superbrain_bridge.js`（导状态 / 注入等价鼠标命令）、`superbrain_kernel.js`（军事：集火、风筝、多军团多方向、压境回防）、`superbrain_economy.js`（经济：农民、田、房、科技、劳力调度、工地保活、兵力生产） |
| `app/` | 零依赖 Node 控制台：REST + SSE、41 条逻辑指令（玩家自然语言和 UI 共用同一 schema）、战略旋钮、训练模式（自动开局 + 参数搜索 + 排行榜）、大模型中间层（OpenAI 兼容，可接本地 Ollama） |
| `tools/` | 离线诚实模拟（`econ_test.mjs` 等，用来在没有引擎的情况下回归经济逻辑）与实盘分析脚本 |
| `sidecar/` | 早期的外部大脑原型（Python 思路的残留，现已由 `app/` 取代） |
| `.qoder/skills/superbrain-console/` | 我（AI）用来驱动这套东西的操作手册：指令表、帧字段含义、旋钮表、排错流程 |

数据流：`mod` 每拍把态势写成 `saves/campaigns/superbrain/run-*/state-*.json`，
`app` 读帧、算决策、回写 `cmd-*.json`，`mod` 再把它转成引擎的网络命令
（`AttackMove` / `OrderGatherers` / `Construct` / `Repair` …），也就是"模拟鼠标"而不是改游戏。

## 怎么跑

1. 需要 Node ≥ 20 和一份 0 A.D. 0.28（游戏安装路径写在 `app/lib/config.mjs` 的默认值里，可改）。
2. 把 `mod/` 放进游戏的 `binaries/data/mods/superbrain`，并在
   `%APPDATA%\0ad\config\user.cfg` 里启用：`mod.enabledmods = "mod public superbrain"`
   （另外建议 `pauseonfocusloss = false`，否则窗口一失焦主循环就停，看着像崩了）。
3. 双击 `superbrain/打开控制台.bat` —— 后端没起会自动拉起，然后打开浏览器到
   `http://127.0.0.1:8712/`。也可以手动：`node superbrain/app/server.mjs`。
4. 页面顶部四个按钮管接管，旋钮管战略；或者直接 `node .qoder/skills/superbrain-console/scripts/sb.mjs <命令>`。

同一时刻**只能有一个 pyrogenesis 实例**：引擎会独占 `public.zip`，第二个实例读不到数据会直接原生崩溃
（crashlog 表现为 `Access violation reading 0x00000018`，没有任何 JS 栈）。控制台已经加了守卫。

## 现在的水平，以及缺点

**军事侧**能用：远程风筝、多编组换方向、集火、基地被压境时全军回防，这些都实盘验证过
（有一局 1v1 打到 Petra 的 Town 阶段并赢下）。刚把"备多少兵"改成跟着敌方可见兵力走
（以前是纯自变量，出现过 兵 5 对 敌方合计 57 的荒谬局面），胜负还不稳定。

**经济系统还很弱**，这是当前主要短板，已知问题：

- 建造太慢：实盘 15 分钟只落出 8~10 栋（田 + 房），床位经常冻死，人口长时间卡在 15~20。
- 至今**没有在 20 分钟实盘内上成 Town**；离线诚实模拟里"12 分钟凑齐 500 粮 + 500 木 + 5 栋"这条线也还没达标。
- 劳力调度追不上缺口：引擎的 `numGatherers` 严重滞后、驻军单位没有坐标、往返路上不计数，
  所以副驾自己维护一套"位置证据 + 下过的采集令"的人手账本，仍然会误判。
- 库存会畸形：石/金囤到 300+ 花不掉，同时木头 0 人在砍。
- 净收入 ≠ 毛收入（边采边花的资源净收入恒为 0），这类坑踩过并修过，但判定阈值仍是拍脑袋的。
- 引擎的拒绝理由读不到，只能靠"命令下出去没生效"倒推，所以有指数退避（`deadRetry`）而不是硬重试。

**没有无头批量对局**：因为上面那个 public.zip 独占锁，"靠成千上万局自对局变强"目前只能串行实盘，
一次几分钟，这是"参数自学习"最大的现实约束。`tools/` 里的离线模拟能回归经济逻辑，但它不是真引擎。
